# Skill: extract-data

이 스킬은 마크다운 공고문 문서(`document.md`)로부터 임대 정보(일정, 조건, 단지, 평형 가격)를 자원 효율적으로 추출하여 정제하고, DB 적재 및 이중 로깅을 자동화하기 위한 에이전트 전용 가이드라인입니다.

---

## 1. 작동 원리 및 수행 지침 (Execution Guidelines)

### 1단계: 마크다운 본문 정밀 슬라이싱 및 병합 (부모 에이전트)
* **목적**: 불필요한 행정 서식 등을 걸러내어 서브에이전트 호출 시 입력 토큰 소모를 70% 이상 절감하면서도 비고 및 각주 정보의 완전무결성을 보존합니다. (구 AGENTS.md 누적 규칙 #9 이관)
* **실행 방식**: 부모 에이전트는 별도의 파서나 슬라이싱 스크립트 파일(예: `slicer.py`, `parser.py` 등)을 프로젝트 내에 생성하여 처리하지 않으며, 오직 직접 `view_file` 도구로 원천 파일을 분석하여 핵심 정보를 직접 판단하고 슬라이싱합니다. (구 AGENTS.md 누적 규칙 #21 이관)
* **슬라이싱 감지 기준**:
  - `일정`, `신청접수`, `보증금`, `임대료`, `한도액`, `지원기준`, `공급대상`, `동호수`, `면적`, `신청자격`, `상호전환`, `전환이율`, `전환율`, `보증금 증액`, `보증금 감액`, `난방`, `지역난방`, `개별난방`, `승강기`, `엘리베이터`, `주차`, `주차장`, `임대조건`, `전환보증금`, `최대전환`, `기본 임대`, `서류제출`, `당첨자`, `계약체결`, `자산`, `소득기준`, `배점`, `선정방법`, `무주택`, `세대구성원`, `재당첨`, `거주요건`, `순위`, `자동차`, `총자산`, `가구원수`, `건강보험`, `우선공급`, `특별공급`, `일반공급`, `신혼부부`, `생애최초`, `다자녀`, `고령자`, `예비자`, `예비입주자`, `동호추첨` 키워드가 들어간 테이블(`|---|`) 및 헤더 영역을 추출합니다.
  - 정보 누락 방지를 위해 감지된 테이블/본문 시작 전 20라인부터 끝난 후 30라인(비고 각주 포함) 컨텍스트를 병합(Merge)합니다.
  - 공고문 후반부에 수록되는 개인정보 동의서, 위임장 양식 등 불필요한 별첨 텍스트는 슬라이싱 대상에서 원천 절단하여 제외합니다.

### 1.5단계: 대형 공고 자동 감지 및 다단계(Multi-stage) 분할 파싱 (부모 에이전트)
* **대상 기준**: 마크다운 파일의 크기가 **80KB 이상**이거나 공고에 포함된 개별 단지(Complex)의 수가 **3개 이상**인 경우를 '대형 공고'로 규정합니다.
* **동작 및 분할**:
  - LLM의 최대 출력 토큰(Max Output Tokens) 제한으로 인해 정보가 누락(특히 JSON의 후반부인 `details` 배열이 `[]`로 짤리는 현상)되는 것을 방지하기 위해, 수치/일정 데이터와 상세 설명 데이터를 독립적으로 분할 파싱합니다.
  - **1차 호출 (수치/일정)**: `schedules`, `limits`, `complexes`, `units` 추출 전용 슬라이싱 블록을 서브에이전트에게 넘겨 해당 정보만 완벽하게 추출하여 임시 JSON 구조를 생성합니다.
  - **2차 호출 (상세 설명)**: `details` 추출에 필수적인 상세 자격 요건, 소득/자산 기준 등 설명형 텍스트 영역(예: 파주시 공고의 308라인 이하 등)만 슬라이싱하여 서브에이전트에게 넘겨 6대 항목의 `details` 배열만 단독 추출합니다.
  - **병합(Merge)**: 1차 결과(수치/일정)와 2차 결과(details)를 부모 에이전트가 병합하여 완결된 `data.json`을 완성합니다.

### 2단계: 서브에이전트 가동 및 data.json 파일 물리 저장 (서브에이전트)
* **공식 설정 조회 의무**: 부모 에이전트는 서브에이전트(`markdown_sql_parser`)를 가동(`define_subagent`)하기 전, 반드시 프로젝트 내 공식 에이전트 설정 파일인 [.agents/agents/markdown_sql_parser/agent.json](file:///home/iru/project03/.agents/agents/markdown_sql_parser/agent.json)을 물리 도구(`view_file`)로 먼저 조회하여 읽어야 합니다.
* **1:1 설정 복사 및 전사 규칙**: 서브에이전트 생성 시 자의적으로 프롬프트를 재구성하거나 창조하지 않으며, 반드시 `agent.json` 파일의 `name`, `description`, `enable_write_tools`, `system_prompt` 설정 항목을 있는 그대로 1:1 복사하여 서브에이전트를 정의 및 실행해야 합니다. 특히 스크립트 작성/실행 금지(`[CRITICAL RESTRICTION]`) 사항이 정확히 주입되도록 보장해야 합니다.
* **동작**: 부모 에이전트가 슬라이싱된 텍스트와 저장할 로컬 경로(`docs/md/{공고_폴더}/data.json`)를 인자로 전달하여 서브에이전트(`markdown_sql_parser`)를 구동합니다.
* **출력**: 서브에이전트는 제공받은 텍스트를 SQLite 테이블 명세에 맞춘 JSON 구조로 파싱하고, 지정된 경로에 `data.json` 파일로 직접 쓰기를 완료한 뒤 부모에게 성공 상태를 보고합니다.

### 2.5단계: 슬라이싱 입력 블록과 data.json 1:1 교차 검증 (부모 에이전트)
* **동작**: 서브에이전트가 `data.json` 파일 저장을 보고하면, 부모 에이전트는 **서브에이전트에게 전송했던 슬라이싱 텍스트 블록 내의 주택 테이블**과 최종 생성된 **`data.json`의 complexes 및 units 개수/이름**을 직접 눈으로 대조 검증(1:1 매핑)해야 합니다.
* **무결성 판정**: 슬라이싱 입력 블록에 기재된 모든 임대 단지 및 평형 조건이 `data.json`에 누락이나 잘림(Truncation) 없이 정확히 변환된 것이 최종 확인된 경우에만 3단계(적재)로 이행합니다. 만약 불일치나 누락이 발견될 경우, 적재를 보류하고 분할 재파싱 등 교정 단계를 밟아야 합니다.

### 3단계: 무컨펌 즉시 적재 및 이중 로깅 (부모 에이전트)
* **적재**: 교차 검증이 통과되어 `data.json` 저장이 확인되면 부모 에이전트는 대기 없이 곧바로 공통 적재 스크립트([insert_loader.py](file:///home/iru/project03/src/parser/insert_loader.py))를 실행하여 `public_housing.db`에 적재를 수행합니다.
* **실행 명령어**:
  ```bash
  ./venv/bin/python src/parser/insert_loader.py docs/md/{공고_폴더}/data.json docs/md/{공고_폴더}/data.json
  ```
* **로깅**: 적재 결과는 SQLite 데이터베이스 내의 `data_load_logs` 테이블에 기록되며, 적재 세부 과정 및 에러 Traceback 정보는 해당 공고 폴더 하위인 `docs/md/{공고_폴절}/load.log` 텍스트 파일에 추가로 파일 보관(이중 로깅)합니다.

### 4단계: 사후 요약 브리핑 및 자동 루프 반복
* **결과 보고**: 적재가 끝난 직후 **"N번째 공고 적재 완료: (공고 ID, 등록 평형 수, 일정 수)"** 결과를 채팅창에 사후 요약 브리핑하고, 중간 사용자 컨펌 없이 9개 공고 전체를 완료할 때까지 루프를 순차적/자동으로 반복 수행합니다.
* **병렬 파이프라이닝**: 배치성 병렬 작업(예: 대용량 데이터 추출 및 변환 등)을 처리할 때는, 전체 대상의 사전 준비 단계(예: 파일 슬라이싱/읽기)가 모두 끝날 때까지 기다리지 않습니다. 먼저 준비가 끝난 소량의 데이터 블록(예: 2~3개)에 대해 서브에이전트 구동 등의 후속 연산 단계를 즉시 백그라운드에서 실행하고, 후속 단계가 돌아가는 동안 남은 사전 준비 작업을 계속 처리하는 파이프라이닝(Overlapping) 방식을 적용하여 작업 지연을 극대화로 방지합니다. (구 AGENTS.md 누적 규칙 #29 이관)
* **감사 주기**: 데이터 적재 정합성을 검증하기 위해 작성된 `audit_db.py` 등의 부가 감사(Audit) 스크립트는 작업 파이프라인의 필수 루프에 포함하여 무의식적으로 매번 반복 실행하지 않으며, 데이터 정합성 검증은 오직 사용자가 명시적으로 요구하거나 데이터 손상 의혹이 있을 때 단발성으로만 구동합니다. (구 AGENTS.md 누적 규칙 #10 이관)

## 2. 데이터 파싱 및 수집 세부 규약 (Data Parsing & Extraction Rules)

### 2.1. 원천 데이터 신뢰 원칙
- 데이터 파싱 및 가공 시 원본 PDF 파일이나 가변적인 외부 폴더 경로에 의존하여 메타데이터를 유추하지 않으며, 오직 대상 마크다운 파일(`document.md`) 본문의 텍스트 및 표 콘텐츠만 원천 데이터로 삼아 정보를 수집합니다.

### 2.2. 행정 서식 제외 (노이즈 필터링)
- 공고문 후반부에 수록되는 개인정보 동의서, 위임장, 빈 서류 양식 및 자기소개서 가이드 등 행정 서식 양식이나 불필요한 별첨 텍스트는 노이즈 데이터로 취급하여 수집 대상에서 제외합니다.

### 2.3. 위치 정보 좌표 변환 위임
- 지도 마커 생성을 위한 주택의 위치 정보 수집 시 위도, 경도 실수형 좌표 데이터를 테이블에 고정하지 않으며, 텍스트 주소(`address`) 정보만 저장하고 클라이언트 지도 라이브러리(Geocoder)의 동적 좌표 변환에 위임하여 스키마를 담백하게 관리합니다.

### 2.4. 정제 데이터 물리 보관 및 이식성 보장
- 서브에이전트가 추출한 JSON 형태의 정제 데이터는 임시 경로에 두지 않고, 각 공고 마크다운 폴더 하위인 `docs/md/{공고_폴더}/data.json`에 물리적인 파일로 보존하여 관리합니다. 또한, 데이터베이스 적재 시 파일 시스템의 절대 경로가 하드코딩되지 않도록 프로젝트 루트 기준 가변 상대 경로로 변환하여 저장함으로써 환경 이식성을 보장합니다.

### 2.5. 50년 공공임대 처리
- 모집 공고 중 '50년 공공임대' 유형은 폴더명과 DB `subscription_type` 모두 `50년공공임대`로 그대로 유지합니다. (표준 사전 항목 별도 정의)

### 2.6. 비정형 주소 자동 표준화 및 검색 교차 검증
- 공고문에 기재된 원본 주소가 표준 도로명이나 지번(번지수/건물번호가 명확히 표기된 형태)을 따르지 않고, 임시 지구 블록명이나 비정형 문구(예: `"도내동 외 일원 고양창릉 공공주택지구 내 A-4블록"`, `"운정 A21BL"`)인 경우, 서브에이전트가 주소를 추출하는 시점에 반드시 웹 검색(`search_web`)을 수행하여 실제 등록된 정식 지번 주소(예: `"경기도 고양시 덕양구 도내동 144-4"`) 또는 도로명 주소를 찾아 정정하여 `data.json`에 저장해야 합니다.
