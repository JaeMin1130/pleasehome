# Skill: extract-data

이 스킬은 마크다운 공고문 문서(`document.md`)로부터 임대 정보(일정, 조건, 단지, 평형 가격)를 자원 효율적으로 추출하여 정제하고, DB 적재 및 이중 로깅을 자동화하기 위한 에이전트 전용 가이드라인입니다.

---

## 1. 작동 원리 및 수행 지침 (Execution Guidelines)

### 0단계: 7대 특성 감지 및 테이블 평탄화 전처리 (부모 에이전트)
* **목적**: 공고의 특성에 따른 파싱 조건 분기화 및 복잡한 마크다운 표의 빈 셀 병합으로 인한 LLM의 구조 해석 실패 방지.
* **실행 방식**: 부모 에이전트는 [pre_processor.py](file:///home/iru/project03/.agents/scripts/pre_processor.py)를 실행하여 7대 기본 특성 플래그(has_complexes, is_distributed 등)를 자동 감지하고, 빈 병합 셀을 위 셀의 값으로 보완하는 전방 충전(Forward Fill) 처리를 수행해 평탄화된 `document_flat.md` 파일을 생성합니다.

### 1단계: 모듈식 프롬프트 조립 및 파싱 (서브에이전트)
* **공식 설정 조회 의무**: 부모 에이전트는 서브에이전트(`markdown_sql_parser_v4`)를 가동(`define_subagent`)하기 전, 반드시 프로젝트 내 공식 에이전트 설정 파일인 [.agents/agents/markdown_sql_parser/agent.json](file:///home/iru/project03/.agents/agents/markdown_sql_parser/agent.json)을 물리 도구(`view_file`)로 먼저 조회하여 읽어야 합니다.
* **동작 및 호출**: `pre_processor.py`에서 감출된 7대 특성 플래그 결과를 바탕으로 프롬프트를 조립하여 `markdown_sql_parser_v4` 서브에이전트를 호출합니다. 서브에이전트는 평탄화된 마크다운 텍스트를 입력받아 임시 저장할 로컬 경로(`docs/md/{공고_폴더}/data.json`)에 JSON 데이터를 생성합니다.

### 2단계: 룰 기반 실시간 정합성 물리 검증 (부모 에이전트)
* **동작**: 서브에이전트가 JSON 저장을 보고하면, 부모 에이전트는 [critic_validator.py](file:///home/iru/project03/.agents/scripts/critic_validator.py)를 호출하여 7대 인자 및 데이터 스키마 기반의 날짜 선후 논리, 상호전환 수학 관계, complexes-units 외래 키 매핑 등을 적재 전에 실시간으로 검증합니다.
* **피드백 루프**: 검증에 실패할 경우, `critic_validator.py`가 출력한 구체적 에러 피드백 메시지를 구성해 서브에이전트에게 전달하여 재추출을 요청하며, 이 피드백 루프는 최대 3회까지 반복 가능합니다.

### 3단계: 최종 적재 및 안전 격리 격차 프로토콜 (Fail-Safe)
* **정상 적재 (SUCCESS)**: 2단계 실시간 검증을 완벽하게 통과한 경우, 공통 적재 스크립트([insert_loader.py](file:///home/iru/project03/.agents/scripts/insert_loader.py))를 정상 구동하여 `public_housing.db`에 최종 적재를 완결합니다.
  ```bash
  ./venv/bin/python .agents/scripts/insert_loader.py docs/md/{공고_폴더}/data.json docs/md/{공고_폴더}/data.json
  ```
* **안전 격리 및 성능 저하 우회 적재 (FAIL)**: 파싱 실패(JSON 파손) 또는 검증 실패 후 피드백 한도(3회)를 초과하여 복구가 불가능한 경우, 적재를 중단하고 `insert_loader.py`를 실패 강제 로깅 모드로 실행합니다.
  ```bash
  ./venv/bin/python .agents/scripts/insert_loader.py --doc_path docs/md/{공고_폴더}/document.md --status FAIL --error_message "구체적 검증 에러 내용"
  ```
  - 이 모드 실행 시 `data_load_logs`에 `status = FAIL`로 실패 기록이 보관되며, 관계형 테이블 대신 공고 기본 정보 레코드 및 `announcement_details`에 전체 마크다운 원본을 통째로 쏟아부어 임시 보관하는 '우아한 성능 저하 적재'를 완결하여 이중 로깅 처리합니다.


### 4단계: 사후 요약 브리핑 및 자동 루프 반복
* **결과 보고**: 적재가 끝난 직후 **"N번째 공고 적재 완료: (공고 ID, 등록 평형 수, 일정 수)"** 결과를 채팅창에 사후 요약 브리핑하고, 중간 사용자 컨펌 없이 9개 공고 전체를 완료할 때까지 루프를 순차적/자동으로 반복 수행합니다.
* **병렬 파이프라이닝**: 배치성 병렬 작업(예: 대용량 데이터 추출 및 변환 등)을 처리할 때는, 전체 대상의 사전 준비 단계(예: 파일 슬라이싱/읽기)가 모두 끝날 때까지 기다리지 않습니다. 먼저 준비가 끝난 소량의 데이터 블록(예: 2~3개)에 대해 서브에이전트 구동 등의 후속 연산 단계를 즉시 백그라운드에서 실행하고, 후속 단계가 돌아가는 동안 남은 사전 준비 작업을 계속 처리하는 파이프라이닝(Overlapping) 방식을 적용하여 작업 지연을 극대화로 방지합니다. (구 AGENTS.md 누적 규칙 #29 이관)
* **감사 주기**: 데이터 적재 정합성을 검증하기 위해 작성된 `audit_db.py` 등의 부가 감사(Audit) 스크립트는 작업 파이프라인의 필수 루프에 포함하여 무의식적으로 매번 반복 실행하지 않으며, 데이터 정합성 검증은 오직 사용자가 명시적으로 요구하거나 데이터 손상 의혹이 있을 때 단발성으로만 구동합니다. (구 AGENTS.md 누적 규칙 #10 이관)

## 2. 데이터 파싱 및 수집 세부 규약 (Data Parsing & Extraction Rules)

### 2.1. 원천 데이터 신뢰 원칙
- 데이터 파싱 및 가공 시 원본 PDF 파일이나 가변적인 외부 폴더 경로에 의존하여 메타데이터를 유추하지 않으며, 오직 대상 마크다운 파일(`document.md`) 본문의 텍스트 및 표 콘텐츠만 원천 데이터로 삼아 정보를 수집합니다.

### 2.2. 행정 서식 제외 (노이즈 필터링)
- 공고문 후반부에 수록되는 개인정보 동의서, 위임장, 빈 서류 양식 및 자기소개서 가이드 등 행정 서식 양식이나 불필요한 별첨 텍스트는 노이즈 데이터로 취급하여 수집 대상에서 제외합니다.

### 2.3. 위치 정보 좌표 변환 위임
- 지도 마커 생성을 위한 주택의 위치 정보 수집 시 위도, 경도 실수형 좌표 데이터를 테이블에 고정하지 않으며, 텍스트 주소(`address`) 정보만 저장하고 클라이언트 지도 라이브러리(Geocoder)의 동적 좌표 변환에 위임하여 스키마를 담백하게 관리합니다.

### 2.4. 정제 데이터 물리 보관 및 이식성 보장
- 서브에이전트가 추출한 JSON 형태의 정제 데이터는 임시 경로에 두지 않고, 각 공고 마크다운 폴더 하위인 `docs/md/{공고_폴더}/data.json`에 물리적인 파일로 보존하여 관리합니다. 또한, 데이터베이스 적재 시 파일 시스템의 절대 경로가 하드코딩되지 않도록 프로젝트 루트 기준 가변 상대 경로로 변환하여 저장함으로써 환경 이식성을 보장합니다.

### 2.5. 50년 공공임대 처리
- 모집 공고 중 '50년 공공임대' 유형은 폴더명과 DB `subscription_type` 모두 `50년공공임대`로 그대로 유지합니다. (표준 사전 항목 별도 정의)

### 2.6. 비정형 주소 자동 표준화 및 검색 교차 검증
- 공고문에 기재된 원본 주소가 표준 도로명이나 지번(번지수/건물번호가 명확히 표기된 형태)을 따르지 않고, 임시 지구 블록명이나 비정형 문구(예: `"도내동 외 일원 고양창릉 공공주택지구 내 A-4블록"`, `"운정 A21BL"`)인 경우, 서브에이전트가 주소를 추출하는 시점에 반드시 웹 검색(`search_web`)을 수행하여 실제 등록된 정식 지번 주소(예: `"경기도 고양시 덕양구 도내동 144-4"`) 또는 도로명 주소를 찾아 정정하여 `data.json`에 저장해야 합니다.

### 2.8. 전세임대 및 전세임대형 공고의 단지(Complexes) 판별 배제 규약
- **대상 및 판별:** 공고 제목이나 본문 시작 10줄 이내 영역에 `전세임대` 또는 `전세임대형` 키워드가 존재하는 융자 지원 유형은 공고 시점에 물리적 단지가 실재하지 않습니다. 따라서 pre_processor.py 감지 룰셋을 통해 `has_complexes = False`로 강력히 규정하여 complexes 및 units 적재를 사전에 완전히 배제시킵니다.
- **예외 대상 (일반 든든전세):** LH 또는 HUG 등 공사 측에서 직접 기존 주택을 사전 매입하여 리스트나 별첨 엑셀로 제공하는 정규 `든든전세` 주택 유형 등은 실제 단지(Complexes)와 평형(Units)이 실존하므로, 본 complexes 배제 규약의 필터링 대상에서 엄격히 제외하여 도메인 무결성을 보장합니다.
