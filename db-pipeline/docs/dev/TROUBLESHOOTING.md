### [이슈 날짜: 2026-07-02] housing_units 테이블의 상호 전환 조건 수치 누락 및 오차 보완 조치
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `public_housing.db` 적재 데이터 중 보증금 전환이 가능한 6개 공고(총 2,229개 유닛)에서 `min_deposit` 및 `max_monthly_rent` 등의 값이 누락(NULL)되거나 불완전하게 적재되어 있음.
* **원인 (Cause)**: 
  * DB 적재 파이프라인에서 상호 전환 요율(증액 6.0%, 감액 3.5%) 및 전환 한도에 대한 계산 검증 로직이 빠진 채 raw 데이터가 적재되어 누락 및 오차가 발생함.
* **해결 (Solution)**: 
  * 가용한 공고 조건에 따라 전환 값을 정밀하게 수식화하여 동적으로 계산(단방향은 기본값 대입, 양방향은 한도값 계산)하여 DB에 보완 업데이트하고 교차 검증을 완료함.

### [이슈 날짜: 2026-06-30] settings.json 내 명령어 허용 설정 누락 및 매칭 조건 불일치
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `settings.json`에 `permissions`를 등록해 두었으나 TUI에서 명령을 실행할 때마다 매번 수동 승인 팝업이 발생함.
* **원인 (Cause)**: 
  * 승인 정책 제어용 `toolPermission` 키가 설정되지 않아 기본값(`"request-review"`)으로 작동하였으며, `allow` 내에 인자를 포함한 너무 긴 명령어 경로를 적어 매칭에 실패함.
* **해결 (Solution)**: 
  * `settings.json`에 `"toolPermission": "always-proceed"`를 추가하고 `allow` 안의 매칭 패턴을 `"command(python)"`과 같이 접두사(Prefix) 수준으로 단순화한 뒤 세션을 재기동함.

### [이슈 날짜: 2026-06-30] complexes와 housing_units 간 단지명 오타(한글/한자 혼용)에 따른 검증 실패
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `critic_validator.py` 구동 시 `complex_name '웰라움퍼펙特시티'은 complexes 목록에 존재하지 않습니다` 에러로 정합성 검증이 실패함.
* **원인 (Cause)**: 
  * 서브에이전트 데이터 추출 과정에서 한자('特')와 한글('트')이 섞여 complexes 선언부와 units 매핑부의 단지명 텍스트 정밀 불일치 발생함.
* **해결 (Solution)**: 
  * `data.json` 내의 units에 잘못 매핑된 단지명을 `'웰라움퍼펙트시티'`로 보정한 후 검증을 통과시킴.


### [이슈 날짜: 2026-06-30] schedules 테이블 적재 중 raw_text KeyError에 따른 롤백
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `insert_loader.py` 적재 시 `schedules` 내 `raw_text` 속성 누락으로 KeyError가 발생하며 트랜잭션 전체가 롤백됨.
* **원인 (Cause)**: 
  * 서브에이전트가 schedules 구조 내의 필수 문자열 컬럼인 `raw_text`를 누락한 채 추출을 완료하여 발생함.
* **해결 (Solution)**: 
  * `data.json`에 `raw_text`를 수동 보정해 적재 완료하고, `critic_validator.py` 및 `agent.json` 지침서에 필수 누락 검증 조건을 추가함.

### [이슈 날짜: 2026-06-30] details 테이블 적재 중 section_content KeyError에 따른 롤백
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `insert_loader.py` 적재 시 `details` 내 `section_content` 키 대신 `content` 키가 오용되어 KeyError 및 롤백이 발생함.
* **원인 (Cause)**: 
  * 서브에이전트가 공식 명세가 아닌 임의의 `content` 키를 생성하여 데이터를 정제하면서 오류가 발생함.
* **해결 (Solution)**: 
  * `data.json` 내 `content` 키를 `section_content`로 정정하고, 검증기와 지침서에 키 준수 및 `sort_order` 누락 체크 룰을 강화함.

### [이슈 날짜: 2026-06-30] housing_units 테이블 적재 중 exclusive_area NOT NULL 제약 위반 롤백
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `insert_loader.py` 구동 시 `NOT NULL constraint failed: housing_units.exclusive_area` 에러와 함께 적재가 실패함.
* **원인 (Cause)**: 
  * 전용면적이 명시되지 않은 단지형 공고에서 `exclusive_area`를 null로 지정하였으나, DB 컬럼에 NOT NULL 제약조건이 걸려 있어 충돌함.
* **해결 (Solution)**: 
  * 본문 면적이 없는 경우 기본값 `0.0`으로 정규화하도록 data.json을 정정하고, 검증기와 지침서에 default 값 주입 규칙을 전수 반영함.

### [이슈 날짜: 2026-06-26] 예비자 전용 모집 공고 적재 조건 불일치
* **분류**: 백엔드
* **현상 (Problem)**: 
  * 예비입주자 모집 공고에서 `supply_count가 0이 아닙니다`라는 정합성 검증 에러 다수 발생함.
* **원인 (Cause)**: 
  * 예비자 모집 공고(is_reserve_only=True) 비즈니스 규칙상 공급량은 0이어야 하고 모집 가구 수는 `reserve_count`에 들어가야 하나, 이전 추출에서 반대로 매핑됨.
* **해결 (Solution)**: 
  * 서브에이전트 추출 규칙을 교정하여 모든 `supply_count`를 0으로 세팅하고 실제 인원을 `reserve_count`로 정상 재배치하여 재적재함.

### [이슈 날짜: 2026-06-26] 가상환경 파이썬 구동 경로 오인 에러
* **분류**: 백엔드
* **현상 (Problem)**: 
  * 루프 스크립트 실행 중 `./venv/bin/python: No such file or directory` 경로 에러 발생함.
* **원인 (Cause)**: 
  * 가상환경 디렉토리명이 `.venv`인데 접두어인 점(`.`)을 누락한 `./venv` 경로를 터미널 명령에 사용함.
* **해결 (Solution)**: 
  * 실행 인터프리터 경로를 `./.venv/bin/python`으로 정확히 정정하여 파이프라인 스크립트를 정상 구동함.

### [이슈 날짜: 2026-06-25] .gitignore 추적 배제 파일 무단 강제 커밋(git add -f) 에러
* **분류**: 백엔드
* **현상 (Problem)**: 
  * `git add` 시 `.gitignore`에 의해 `AGENTS.md` 등 환경 문서가 배제됨을 무시하고 강제 추가(`-f`) 옵션으로 억지 커밋함.
* **원인 (Cause)**: 
  * 프로젝트 버전 관리 정책과 형상 통제 규약을 망각하고 작업 편의를 위해 일괄 강제 커밋 옵션을 자의적으로 남용함.
* **해결 (Solution)**: 
  * 강제 커밋 취소(`git reset HEAD~1`) 후 추적 허용된 소스 파일만 정상 커밋하도록 롤백 및 `-f` 옵션 사용 절대 금지 규약 신설.

### [이슈 날짜: 2026-06-25] Geocoding API 좌표 변환 시 인증 거부 (210/401 에러)
* **분류**: 백엔드
* **현상 (Problem)**: 
  * 데이터 파이프라인에서 텍스트 주소를 위경도로 변환하기 위해 네이버 지도 API 호출 시 지속적인 인증 거부 에러 반환.
* **원인 (Cause)**: 
  * 백엔드의 서버 간 통신은 브라우저 환경(CORS 등)과 달라 클라이언트용 웹 도메인을 그대로 사용할 수 없으며, NCP Geocoding 전용 런타임 호환 엔드포인트 분리가 누락됨.
* **해결 (Solution)**: 
  * 백엔드의 Geocoding 서버 간 통신 특성을 파악하여, 프론트엔드 클라이언트와 달리 런타임 호환용 전용 도메인(`maps.apigw.ntruss.com`)을 엔드포인트로 명확히 분리하여 호출하도록 통신 규격 수정.

### [이슈 날짜: 2026-06-25] SQLite 컬럼 Comment 속성 미지원 및 메타데이터 표출 한계
* **분류**: 백엔드
* **현상 (Problem)**: 
  * 데이터베이스 스키마 설계 시 시스템 수준의 컬럼 주석(Comment) 파싱을 SQLite 엔진 자체가 지원하지 않아, GUI 조회 툴 등에서 논리적 메타데이터를 확인할 수 없음.
* **원인 (Cause)**: 
  * SQLite의 경량 데이터베이스 구조적 특성상 표준 SQL의 `COMMENT ON COLUMN` 문법이 시스템 테이블 레벨에서 공식 지원되지 않음.
* **해결 (Solution)**: 
  * 무리한 DB 구조 변형을 배제하고 엔진 제약 사항을 수용하는 대신, 개발 규약 문서(`PROJECT.md`) 내에 테이블/컬럼 단위 메타데이터 명세서를 구축해 단일 진실 공급원(SSOT) 마련.

### [이슈 날짜: 2026-06-25] Geocoding API 주소 파싱 실패 및 정밀도 하락 (마커 누락)
* **분류**: 백엔드
* **현상 (Problem)**: 
  * 일부 신도시 주소나 비표준 도로명, 괄호가 포함된 주소를 통째로 넘길 경우 네이버 Geocoding API가 좌표 변환에 실패하여 지도상에 단지 마커가 아예 누락됨.
* **원인 (Cause)**: 
  * 정제되지 않은 원본 주소 텍스트의 상세번지 수준까지 API가 매칭을 시도하다 정밀 불일치로 실패 처리됨.
* **해결 (Solution)**: 
  * 1차 변환 실패 시 주소의 뒷단어를 읍/면/동 단위 마지노선까지 하나씩 잘라내며 재시도하는 폴백(Fallback) 검색 알고리즘을 도입. 동시에 불완전 매핑 여부를 구분하기 위해 DB에 `is_imprecise` 플래그를 추가하여 무결성 통제.
