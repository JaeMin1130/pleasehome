# 포트폴리오 STAR 기법 개발 여정 꼭지 리스트

본 문서는 공공주택 공고 자동 정제 및 지도 기반 대시보드 프로젝트 개발 과정에서 도출한 핵심 기술적 성과와 문제 해결 경험을 STAR(Situation, Task, Action, Result) 프레임워크에 맞추어 정리한 포트폴리오 작성용 가이드라인입니다.

---

## 📌 포트폴리오용 STAR 기법 핵심 꼭지 7선

### 1️⃣ 비정형 모집 공고 PDF -> 표준 마크다운 자동 표준화 파이프라인 구축
* **분야:** 데이터 엔지니어링 / 파이프라인 구축
* **Situation (상황):** LH, SH 등 여러 공공기관에서 발행하는 임대주택 공고 PDF는 표의 병합 형태, 텍스트 배치 구조가 다르고 매우 복잡하여 바로 데이터베이스화하거나 대시보드에 연동하기 어려웠습니다.
* **Task (과제):** 데이터 유실 없이 문서의 레이아웃과 테이블 정보, 텍스트 흐름을 그대로 유지하며 기계가 파싱하기 좋은 마크다운(Markdown) 문서로 자동 변환해 주는 표준화 파이프라인 개발이 필요했습니다.
* **Action (행동):** `opendataloader-pdf` 라이브러리와 Java 기반 PDF 분석 엔진을 활용한 Python 통합 스크립트(`convert_pdf_to_md.py`)를 개발했습니다. 수동 변환을 넘어 미분류 PDF를 자동 감지하고 일괄 변환 처리하는 전체 스캔 및 변환 자동화 시스템을 완성했습니다.
* **Result (결과):** 수작업 대비 문서 정규화 속도를 획기적으로 개선하였으며, 제각각이었던 PDF 형식을 일관된 단일 마크다운 포맷으로 표준화하여 후속 LLM 정밀 데이터 추출 단계의 성공률을 향상시켰습니다.

### 2️⃣ LLM 서브에이전트 기반 정밀 데이터 추출 및 이중 무결성 검증/감사 시스템
* **분야:** 데이터 무결성 제어 / LLM 에이전트 설계
* **Situation (상황):** 마크다운으로 변환된 공고문 내 복잡한 신청 자격 조건, 소득/자산 기준, 공급 평형별 상세 조건(보증금/월세) 등의 수치 데이터가 DB에 단 1원이나 1㎡라도 잘못 들어가면 서비스 신뢰성이 완전히 붕괴되는 심각한 리스크가 존재했습니다.
* **Task (과제):** LLM 추출 데이터의 부정확성(Hallucination) 및 적재 중 발생할 수 있는 스키마 충돌을 차단하고, 100% 무결성을 가진 클린 데이터를 구축해야 했습니다.
* **Action (행동):** 다음과 같이 4단계 파이프라인을 설계 및 구현했습니다.
  1. **0단계(전처리):** `pre_processor.py`를 통해 테이블 병합 해제 및 평탄화 전처리 수행.
  2. **1단계(추출):** LLM 서브에이전트(`markdown_sql_parser`)를 가동하여 마크다운 본문에서 단지/평형/금액 조건의 규격화된 JSON 데이터 추출.
  3. **2단계(검증):** `critic_validator.py`를 통해 데이터 유형 및 수학적 정합성을 실시간 자동 검증.
  4. **3단계(적재 및 격리):** `insert_loader.py`를 실행하여 SQLite에 데이터 적재. 적재 실패 시 강제 중단이 아닌 에러 격리 및 성능 저하 적재 처리를 보장하고 `data_load_logs` 테이블에 상세 실행 결과를 이중 로깅.
  5. **4단계(감사):** `audit_db.py` 스크립트를 통해 DB 전체 무결성 검출 및 누락 공고 감시 경보 가동.
* **Result (결과):** 적재 전 자동 무결성 검증 필터를 통해 휴먼 에러 및 LLM 파싱 오류로 인한 DB 오염을 완벽히 차단하고, 100% 검증 완료된 입주 조건 데이터를 DB에 유지할 수 있었습니다.

### 3️⃣ 독립 실행과 서버 비용 최적화를 위한 7개 테이블 관계형 데이터베이스 아키텍처 설계
* **분야:** 데이터베이스 모델링 / 비용 최적화
* **Situation (상황):** 하나의 모집 공고 아래에는 다수의 모집 단지(Complex)가 존재하고, 각 단지 내에는 청약 대상 계층(대학생, 신혼부부 등)과 소득 기준별로 임대보증금과 월세 조건이 다르게 매칭되는 1:N 복잡한 데이터 구조를 지니고 있었습니다.
* **Task (과제):** 복잡하게 얽힌 청약 조건을 쿼리하기 쉬우며, 향후 배포 단계에서 무거운 데이터베이스 서버 인프라 유지 비용이 들지 않는 효율적인 RDBMS 스키마를 설계해야 했습니다.
* **Action (행동):** 파일 기반의 경량 관계형 데이터베이스인 SQLite와 비동기 가공 성능이 뛰어난 Node.js 라이브러리 `better-sqlite3`를 결합하여 설계했습니다.
  * 공고 기본 메타데이터(`announcements`), 청약 일정(`announcement_schedules`), 요약 상세(`announcement_details`), 전세 한도 지원(`announcement_limits`), 모집 단지(`complexes`), 단지별 공급 유닛 조건(`housing_units`), 적재 로그(`data_load_logs`) 등 7개의 테이블로 정규화 스키마를 설계하고 효율적인 외래키(FK, Cascade) 관계를 부여했습니다.
* **Result (결과):** PostgreSQL/MySQL 같은 별도 DB 인프라 운영 비용을 0원으로 만들면서도, 파일 백업 및 마이그레이션이 매우 손쉬운 고성능의 독립 실행형 로컬 릴레이션 스토리지 아키텍처를 완성했습니다.

### 4️⃣ 네이버 지도 API 연동 및 지오코딩(Geocoding) 폴백을 통한 시각화
* **분야:** API 연동 / 프론트엔드 시각화 / 예외 처리
* **Situation (상황):** 사용자는 임대 주택 단지의 텍스트 주소 정보만으로는 주변 인프라, 직주근접, 역세권 여부를 직관적으로 판단할 수 없었습니다.
* **Task (과제):** Naver Maps API를 활용해 데이터베이스에 저장된 수많은 단지 주소를 브라우저 상에 매끄럽게 마커로 지도에 매핑해야 했습니다.
* **Action (행동):** Next.js 환경에서 `Map.tsx` 컴포넌트를 설계했습니다.
  * 공고 단지의 주소 텍스트를 Geocoder API를 거쳐 실시간 위경도 좌표로 파싱하여 마커를 그렸습니다.
  * 비정형 주소나 옛 주소로 인해 Geocoding API가 좌표 변환에 실패하는 경우를 대비하여, 기본 좌표 이동 거부 및 예외적 디폴트 좌표 위치 고정을 지원하는 예외 폴백 로직을 설계했습니다.
* **Result (결과):** 텍스트 기반 단지 정보를 지리 정보 마커와 연동하여 정보의 직관성을 극대화했고, API 좌표 매핑 에러율을 완전히 상쇄하는 안정적인 지도 인터페이스를 제공했습니다.

### 5️⃣ Next.js App Router 기반 다차원 동적 필터 및 슬라이딩 아웃 UI/UX 구현
* **분야:** 풀스택 개발 / UI·UX / 트러블슈팅
* **Situation (상황):** 지도 대시보드에서 필터 조건이 바뀔 때마다 전체 페이지가 새로고침되거나 동적 정보 렌더링이 느려지면 사용자 경험이 급격히 악화될 위험이 있었습니다.
* **Task (과제):** [사이드바 | 지도] 양분형 화면 레이아웃에서 끊김 없는 dynamic 데이터 필터링을 구현하고, 단지 마커나 카드를 클릭했을 때 우측에서 평형별 세부 임대 조건을 슬라이딩 뷰로 깔끔하게 노출해야 했습니다.
* **Action (행동):** 
  * Next.js App Router의 Route Handler를 통해 클라이언트 요청에 따라 실시간 쿼리를 연산하는 RESTful API를 작성했습니다.
  * 필터 폼 조작 시 React State가 변하며 지도의 마커와 사이드바(`Sidebar.tsx`)의 단지 리스트가 동기적으로 재렌더링되게 설계하고, 선택 단지는 `DetailPanel.tsx`를 통해 오버레이 슬라이딩 아웃되도록 UX를 고도화했습니다.
  * **[트러블슈팅]** SQLite 데이터베이스는 Boolean 타입을 네이티브하게 지원하지 않고 `0`/`1` 정수형으로 반환하는데, TypeScript의 엄격한 비교문(`===`)으로 인해 필터링 작동이 무시되는 오작동을 발견했습니다. 이를 단순 타입 우회가 아닌 런타임 값 변환 및 Type Assertion(`as any` 캐스팅 후 명시적 형변환)을 통해 안전하게 일치 비교를 수행하도록 해결하여 필터 신뢰성을 복구했습니다.
* **Result (결과):** 복잡한 청약 매물 탐색 소요 시간을 대폭 감축했으며, Seamless하고 현대적인 대화형 UI를 통해 상용 아파트 거래 플랫폼 수준의 사용성을 확보했습니다.

### 6️⃣ 바닐라 CSS 전역 디자인 토큰 시스템 구축 및 하드코딩 매직 넘버 원천 차단
* **분야:** 스타일링 아키텍처 / 리팩토링 / 무결성 제어
* **Situation (상황):** 여러 컴포넌트 파일의 CSS와 인라인 스타일에 색상 코드(Hex, 원시 키워드 white/black), `border-radius: 50%`, `max-height: 80vh`, `flex: 1` 같은 임의의 매직 넘버와 수치 단위가 하드코딩되어 있어, 일관된 스타일 튜닝 및 테마 확장이 극도로 난해했습니다.
* **Task (과제):** 프론트엔드 스타일 코드의 100% 무결성을 보장하고 단 하나의 글로벌 CSS 변수 선언문으로 전체 레이아웃과 컬러 감성을 미세 튜닝할 수 있는 순수 바닐라 CSS 기반 디자인 시스템을 정립해야 했습니다.
* **Action (행동):** `globals.css` 파일에 중앙 스타일 토큰(Colors, Spacing Scale, Fonts, Border Radius, Layout Flex/Z-index)을 구축했습니다.
  * CSS 모듈(`*.module.css`) 내의 사소한 레이아웃 요소까지 전수조사하여 전역 토큰 변수로 치환했습니다.
  * 미세 튜닝이 불가피한 마진이나 패딩 간격 등은 픽셀 하드코딩으로 회귀하지 않고 `calc(var(--spacing-md) * 0.75)`와 같이 기준 토큰에 대한 배율 연산만을 허용하도록 설계 제약을 수립했습니다.
* **Result (결과):** 컴포넌트 레벨에서의 하드코딩 수치 사용률 0%를 달성했습니다. 이 덕분에 전역 디자인 토큰 파일 단 한 곳만 수정하면 웹 서비스 전체의 글꼴 크기, 둥글기 비율, 테마 컬러, 반응형 레이아웃 간격이 연동되어 일괄 갱신되는 유연하고 확장 가능한 디자인 아키텍처를 완성했습니다.

### 7️⃣ 저사양 클라우드 인프라 최적화 배포 및 보안 통제 (NCP Micro + Nginx 리버스 프록시)
* **분야:** 인프라 / DevOps / 비용 최적화
* **Situation (상황):** 고비용 클라우드 아키텍처 대신 초저가 저사양 가상 서버(NCP Micro 등)에 Next.js 풀스택 빌드를 구동할 경우, 메모리가 부족하여 빌드 단계에서 CPU 100% 팬 현상이 발생하거나 런타임에 서버가 다운되는 OOM(Out Of Memory) 장애 위험이 상존했습니다.
* **Task (과제):** 한정된 서버 자원 아래에서도 24시간 중단 없는 고성능 가동 상태를 보존하고, HTTPS 보안 통신 및 악의적인 디도스식 무차별 요청에 대비한 방어선을 구축해야 했습니다.
* **Action (행동):** 
  * 리눅스 운영체제 단에서 가상 디스크 스왑(Swap Memory) 영역을 임시 활성화하여 물리 RAM의 한계를 극복했습니다.
  * Node.js 백엔드를 외부 위협으로부터 직접 노출시키지 않기 위해 Nginx를 리버스 프록시로 전면에 배치하고, 비정상적 트래픽 집중을 물리적으로 잠그는 Rate Limit(요청 속도 제한) 모듈을 적용했습니다.
  * 도메인 연결 후 Let's Encrypt를 활용한 SSL HTTPS 인증서 자동 발급 및 갱신 프로세스를 완비했습니다.
  * 이 모든 프로덕션 인프라 구성 및 명령어 릴리즈 절차를 규격 문서(`DEPLOYMENT.md`)로 구조화하여 인수인계 및 운영 편의성을 높였습니다.
* **Result (결과):** 고가의 전용 웹 서버 운영비 없이도 24시간 안정적으로 서비스가 가능한 무장애 프로덕션 배포 파이프라인을 완료하였습니다.
