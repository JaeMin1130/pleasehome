# 설계 의사결정 기록 (Architecture Decision Records - ADR)

### [2026-07-16] #1. 찜한 공고 및 숨김 기능의 상호 베타적(Exclusive) 로직 채택
* **결정 사항**: 찜하기 활성화 시 숨김 자동 해제, 숨김 활성화 시 찜하기 자동 해제 방안 채택함
* **배경 & 맥락**: 숨김(부정적 관심)과 찜(긍정적 관심)은 논리적으로 상충되므로 두 상태가 동시 공존하지 않게 함으로써 데이터 정합성과 직관적인 사용자 경험을 보장하고자 함
* **상태**: 승인됨 (Accepted)

### [2026-07-21] #2. 공고 DB와 회원 DB 분리(Dual DB) 구조 채택
* **결정 사항**: 공고 데이터 DB(public_housing.db)와 회원 전용 DB(user_data.db)를 완전히 분리함
* **배경 & 맥락**: 배포 시 공고 DB scp 덮어쓰기로 인한 실서버 회원 데이터 유실을 근본적으로 차단하고 Read-Only 공고 서빙과 Read-Write 회원 관리를 명확히 격리함
* **상태**: 승인됨 (Accepted)

### [2026-07-21] #3. 화면 테마(theme) 전용 localStorage 제한 및 전역 다크모드 적용
* **결정 사항**: 북마크/숨김/찜 등의 비회원 데이터를 localStorage에서 제거하고 테마(theme) 설정에만 한정 적용함
* **배경 & 맥락**: 비회원 데이터의 클라이언트 로컬 저장에 따른 복잡도를 차단하고 회원 API 기반 데이터 관리를 일원화함
* **상태**: 승인됨 (Accepted)

### [2026-07-21] #4. 메인 페이지 SSR 하이브리드(서버 렌더링 + 정적 텍스트/링크 + 클라이언트 지도) 구조 채택
* **결정 사항**: 메인 페이지(page.tsx)를 SSR 서버 컴포넌트로 전환하고 지도 및 대화형 UI를 HomeClientLayout 클라이언트 컴포넌트로 분리함
* **배경 & 맥락**: 구글 애드센스 가치가 별로 없는 콘텐츠 및 소유권 거절 이슈를 해결하고, 검색엔진(SEO) 크롤러에게 프리렌더링된 정적 텍스트와 하이퍼링크를 제공하여 검색 유입 및 광고 승인을 보장함
### [2026-07-21] #5. 공고 목록 API의 N+1 SQL 쿼리 최적화
* **결정 사항**: 공고 상세/일정/제한사항 개별 쿼리 조회를 In-Memory Map 대량 로드로 전환함
* **배경 & 맥락**: 루프 기반 N+1 SQL 쿼리로 인한 DB 병목 및 API 응답 지연을 해소함 (300+개 쿼리 -> 4개)
* **상태**: 승인됨 (Accepted)

### [2026-07-21] #6. Sidebar 컴포넌트 서브 탭 단위 분리 모듈화
* **결정 사항**: Sidebar.tsx 내 inline JSX 탭들을 SearchTab, BookmarkTab, MoreTab 컴포넌트로 분리함
* **배경 & 맥락**: 1,400라인 이상의 거대한 단일 Sidebar 컴포넌트를 서브 탭 단위로 분리하여 유지보수성 및 코드 가독성을 향상시킴
* **상태**: 승인됨 (Accepted)

### [2026-07-22] #7. 기본 생성 북마크 폴더('default')의 완전한 제거
* **결정 사항**: 기본 생성되던 북마크 폴더('default') 및 관련 강제 예외 처리들을 프로젝트 전반에서 영구히 삭제함
* **배경 & 맥락**: 비회원과 신규회원의 데이터 관리를 일관되게 단일화하고 사용자가 자유롭게 폴더를 관리할 수 있도록 가이드함. 폴더 삭제 시 아이템 동반 삭제 처리 및 저장 모달 내 폴더 부재 시의 UI/UX 엣지 케이스 방어 코드를 적용함
* **상태**: 승인됨 (Accepted)

### [2026-07-23] #8. 단지 및 공고 상세 정보 탭별 조건부 패널 분기 및 지도 연쇄 연동 구조 채택
* **결정 사항**: 단지 탭(`COMPLEX`) 클릭 시 상세 패널 내 주택형 표 대신 연관 공고 아코디언을 노출하고, 타 탭에서 진입 시에는 기존 평형 표(`UnitTable`)가 유지되는 분기형 `DetailPanel` 구조를 채택함
* **배경 & 맥락**: 공고 탭의 원래 분석 탐색 성능을 100% 보존하면서도, 단지 탭에서 단지명 및 주소 기반으로 공고 정보와 세부 임대 조건을 유기적(아코디언 토글 제자리 열기)으로 탐색할 수 있도록 편의성을 극대화함. 또한 탭 전환 시 상세 정보와 주소창 파라미터가 꼬이는 쿼리 연동 오류를 해결하기 위해 탭 전환 즉시 상태를 리셋함
* **상태**: 승인됨 (Accepted)

### [2026-07-23] #9. 지역 필터링의 O(1) 캐싱 맵 룩업 및 단절식 2단계 폴백 적용
* **결정 사항**: 900개 단지 루프 순회(O(N)) 대신 공고 ID -> region 매핑 해시맵을 생성하여 O(1) 룩업을 구동하고, 공고 지역명이 있을 때는 주소 파싱을 건너뛰는 단절식 폴백을 채택함
* **배경 & 맥락**: 단지 필터링 및 검색창 타이핑 시 O(C * A) 복잡도로 인한 렌더링 병목 및 문자열 연산 과부하를 원천 차단하여 사용자 응답 속도를 개선함
* **상태**: 승인됨 (Accepted)

### [2026-07-23] #10. 모바일 뷰 탭 감춤 대응을 위한 백업 상태(lastActiveTab) 폴백 구조 채택
* **결정 사항**: 모바일 뷰에서 사이드바가 닫힐 때 `activeTab` 대신 백업 탭(`lastActiveTab`)을 폴백으로 지도 마커 및 조건부 상세 패널에 활용하는 구조를 채택함
* **배경 & 맥락**: 모바일 화면 규격 확보를 위해 `activeTab`이 `null`로 바뀌는 UI 레이아웃의 부작용(마커 증발, 패널 분기 꼬임)을 차단하여 뷰의 일관성과 지도 스크롤을 복원함
* **상태**: 승인됨 (Accepted)

### [2026-08-27] #11. Kotlin + Spring Boot 백엔드 분리 및 3단 분리(3-Tier) 아키텍처 채택
* **결정 사항**: 기존 Next.js API Routes 및 DB 직접 접근 방식을 분리하여 Kotlin + Spring Boot 3.x 기반의 독립 REST API 서버를 구축하고 3단 분리(db-pipeline + backend + web) 구조를 채택함
* **배경 & 맥락**: 엔터프라이즈 레벨의 안정성, 트랜잭션 무결성(@Transactional), 계층형 아키텍처 및 QueryDSL 동적 쿼리 최적화를 달성하고, 실무 표준(Spring Boot + Next.js)에 부합하는 구조로 마이그레이션하여 백엔드 역량을 극대화함
* **상태**: 승인됨 (Accepted)

### [2026-08-27] #12. Nginx 기반 /api/ 직접 리버스 프록시 및 PM2 프로세스 매니저 통합 관리
* **결정 사항**: 웹 서버(Nginx)에서 `/api/*` 경로를 Spring Boot(8080)로 직접 리버스 프록시하고, 실서버 백엔드를 PM2(`pleasehome-backend`) 프로세스로 등록 관리함
* **배경 & 맥락**: Next.js Standalone rewrites 프록시의 클라이언트 AJAX 통신 한계를 극복하고, 네트워크 지연(2중 홉) 없는 직접 통신 및 SSH 세션 종료 시에도 백엔드가 무중단 자동 재기동되도록 인프라를 표준화함
* **상태**: 승인됨 (Accepted)
